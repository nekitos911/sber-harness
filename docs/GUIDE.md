# Руководство пользователя sber-harness

Это руководство для тех, кто будет передавать работу агентам и следить за ней: разработчика, который впервые работает с агентами, и аналитика, который не знает git. Всё, что описано ниже, есть в интерфейсе. Названия кнопок и экранов даны в «ёлочках» так, как они написаны в программе.

## 1. Что это и зачем

sber-harness — локальная веб-программа. Она запускается на вашем компьютере и открывается в браузере по адресу `http://127.0.0.1:4777`. Ничего не уходит в сеть: нет внешних шрифтов, аналитики и проверок обновлений. Сами агенты, конечно, ходят туда, куда ходит их собственная программа (например, GigaCode CLI к своей модели), но сам harness только показывает их работу и управляет ею.

Зачем она нужна. Обычно задачу агенту печатают в терминале и ждут, глядя в чёрное окно. Здесь вы передаёте задачу один раз (ссылкой на задачу из трекера, ключом вроде `PROJ-123` или обычной фразой), а дальше агент сам:

- выбирает нужный проект среди ваших;
- создаёт для задачи отдельную ветку и отдельную рабочую копию, чтобы не трогать вашу основную;
- при необходимости запускает помощников, и каждый из них работает в своём чате.

Вы видите с первого взгляда, кто работает, кто ждёт именно вас, кто завис, а кто закончил. Вы отвечаете на вопросы и разрешения, смотрите изменения, делаете коммит, отправляете ветку, открываете пулл-реквест и следите за ним до вливания.

### Словарик

Если вы раньше не работали с git, прочитайте этот список один раз.

- **Агент** — программа с языковой моделью (здесь это GigaCode CLI), которая читает код, правит файлы и запускает команды по вашему заданию.
- **Чат** — разговор с одним агентом. У каждого чата своя история. Каждое ваше сообщение продолжает тот же разговор.
- **Ход агента** — один отрезок работы агента между вашим сообщением и его ответом. Пока идёт ход, агент «работает».
- **Субагент, помощник** — дополнительный агент, которого запускает основной агент для части работы: например, сделать ревью или изучить код. В harness каждый помощник виден отдельным чатом под основным.
- **Репозиторий, проект** — папка с кодом, за которой следит git.
- **Ветка** — отдельная линия изменений. Агент работает в своей ветке (по умолчанию `feature/<ключ задачи>`), поэтому основной код не портится, пока вы не согласились на изменения.
- **Рабочее дерево (worktree)** — отдельная папка с копией проекта, привязанная к ветке. Благодаря ей несколько задач идут одновременно и не мешают друг другу. В боковой панели оно называется «рабочее дерево».
- **Коммит** — зафиксированный набор изменений с коротким описанием. Это «сохранение» в истории проекта.
- **Push** — отправка коммитов вашей ветки на общий сервер (в `origin`), чтобы их увидели другие.
- **Пулл-реквест (PR)** — запрос «влейте мою ветку в основную». Коллеги смотрят изменения, оставляют замечания и одобряют.
- **Влить (merge)** — принять изменения из ветки в основную. После вливания PR считается завершённым.
- **Трекер задач** — система, где живут задачи с ключами вроде `PROJ-123` (в этой версии настроен onework). Подключать его не обязательно.
- **MCP** — способ подключить к агенту или к harness внешний сервис (трекер, сервис пулл-реквестов). Каждый такой сервис называется MCP-сервером.

## 2. Установка и запуск

Нужно:

- Node.js версии 22 или новее;
- git;
- GigaCode CLI. Для знакомства без него хватит демо-режима (см. ниже).

Команды выполняются в папке с harness:

```
npm install
npm run build
npm start
```

После `npm start` откройте в браузере `http://127.0.0.1:4777`. Сервер слушает только `127.0.0.1`, то есть доступен только с вашего компьютера. Если страница пишет «Сервер harness недоступен», значит, сервер не запущен: запустите `npm start` и нажмите «Повторить».

Для разработки самого harness есть `npm run dev` (то же самое, но с горячей перезагрузкой интерфейса).

### Где лежат настройки

- `harness.config.json` — настройки по умолчанию, лежат в репозитории. Их не меняют.
- `harness.config.local.json` — ваши настройки для этого компьютера. Файл не попадает в git и накладывается поверх основного. Экран «Настройки» сохраняет изменения именно сюда.
- Файл секретов — токены и пароли для MCP-серверов. Он лежит вне репозитория. Путь к нему задаётся переменной окружения `HARNESS_MCP_SECRETS` (или `CONSOLE_MCP_SECRETS`) либо ключом `mcpSecretsFile` в локальной конфигурации. Секреты никогда не записывают в сам конфиг, а на экране «Настройки» они не показываются.
- Папка `data/` рядом с harness — история чатов, задачи, служебные данные. Она создаётся автоматически.

Чтобы посмотреть, какие пути и какой агент выбрал harness, выполните `node server/index.js --print-config`.

### Демо без GigaCode

Чтобы попробовать интерфейс без настоящего агента, есть учебный агент `mock`. Самый простой способ:

```
npm run demo
```

Демо запускается на `http://127.0.0.1:4778` со своей папкой данных `data-demo/`: в ней два тестовых репозитория, несколько задач и игрушечные «трекер» и «сервис PR». Папку `data-demo/` можно удалить, и демо начнётся заново.

Если хотите другой порт или другую папку данных, добавьте `--port <номер>` и `--data-dir <пустая папка>`:

```
node server/index.js --demo --port 4830 --data-dir D:\temp\harness-demo
```

В обычном запуске `mock` тоже доступен: создайте чат с агентом `Mock agent` и отправьте сообщение `#spawn create file hello.txt #done`. Появится чат помощника, а основной чат получит его отчёт.

## 3. Первый запуск

На новом компьютере мастер «Ваше рабочее место» открывается на главной, если нужно подключить агента или открыть проект. Для первого чата достаточно пройти эти два шага. Своя команда и навык помощников доступны в свёрнутом разделе «Команда для задач и помощники».

### Шаг 1. «Агент»

Harness проверяет, что агент запускается.

- Если всё хорошо, вы увидите «GigaCode найден: <путь>» и галочку.
- Если агента нет, будет написано, что он не найден на этом компьютере. Укажите путь к его запуску (например, к `gigacode.cmd` в Windows) в поле «Путь к агенту» и нажмите «Проверить».
- Если включено несколько агентов, появится выпадающий список «Агент».
- Если агент просит войти, под шагом появится предупреждение. Войдите в него в терминале или по ссылке из первого чата. Позже вход можно сделать кнопкой «Войти в GigaCode» в «Настройки» → «Рабочее место».

### Шаг 2. «Где ваши проекты»

Агенту нужно знать, где искать код. Есть два варианта.

1. **У вас есть одна папка, в которой лежат все проекты.** Нажмите «Папка со всеми проектами…» и выберите её. Агент сам выберет нужный проект под каждую задачу. В боковой панели эта папка называется «Все проекты».
2. **Папки нет, вы работаете с одним или несколькими проектами.** Нажмите «Открыть проект…» и укажите папку проекта (или используйте кнопку с папкой в заголовке «Проекты» в боковой панели).

Шаг считается выполненным, если указана папка со всеми проектами или открыт хотя бы один проект. Позже папку проектов можно сменить кнопкой «Другая папка с проектами…».

### Шаг 3. «Есть ли у вас своя команда для задач?» · необязательно

Некоторые заводят в агенте свою команду, которая ведёт задачу по шагам: разобраться, сделать, проверить, открыть PR (например, `/full-task`). Если такой нет, ничего страшного: агент получит задачу как есть.

- **«Нет»** (по умолчанию). Агент получает название, описание и ссылку на задачу из трекера, либо вашу фразу, и дальше работает сам.
- **«Есть»**. Впишите команду в поле, например `/full-task`. Если у агента нашлись свои команды или навыки, они показаны рядом («нашлись у агента:»), на них можно нажать. Harness будет ставить команду перед задачей.

Ниже показано, что именно получит агент для задачи PROJ-123: при «Нет» это текст задачи со ссылкой, при «Есть» — например `/full-task https://tracker/…/PROJ-123`.

Своя команда сохраняется в `harness.config.local.json` на вашем компьютере. Обновления программы её не затирают.

### Необязательно: «Показывать помощников агента»

Иногда агент зовёт на помощь другого агента — например, проверить код свежим взглядом. Если включить переключатель, каждый такой помощник появится в программе отдельным чатом: видно, что он делает, ему можно ответить или остановить. Если не включать, помощники работают внутри агента незаметно. Для этого в папку агента запишется файл с инструкцией (навык). Пункт виден, только если навык ещё не установлен.

### Подключение трекера и хостинга кода

После первого запуска откройте **Настройки → Подключения**. Здесь видны сервисы из настроек GigaCode и отдельные подключения Harness. Для чата этот шаг можно пропустить.

1. Если сервис уже есть в списке, выберите его в разделе «Трекер задач» или «Пулл-реквесты». Если его нет, нажмите «Добавить сервер», введите имя и адрес MCP для HTTP либо исполняемый файл для локальной команды. Каждый аргумент команды вводится с новой строки.
2. Если сервис требует авторизацию, нажмите «Ключ» рядом с его именем. Укажите имя HTTP-заголовка или переменной окружения для команды и полное значение, которое ожидает сервер (например, с префиксом `Bearer ` для соответствующей схемы). Harness запишет значение в файл секретов на этом ПК.
3. Нажмите «Проверить» в разделе нужной интеграции. Harness проверит, отвечает ли сервер и предоставляет ли инструменты для задач или PR. Для импорта задач включите «Импорт задач», добавьте код своего пространства и сохраните настройки.

Сервисы, созданные в интерфейсе, можно исправить кнопкой «Изменить». Действия с подключением и ключом применяются сразу. Переключатель в строке сервиса управляет его доступностью для Harness.

### Завершение

- «Начать работу» активна, когда агент найден и указано, где проекты.
- «Пропустить» закрывает мастер. Уже открытые проекты и выбранная папка сохраняются. Он больше не появится сам.

### Как открыть мастер снова

«Настройки» → в правом верхнем углу ссылка «Мастер первого запуска».

## 4. Как дать задачу

Есть три способа: с экрана «Главная», с экрана «Задачи» и просто чатом.

### 4.1. Чат и передача задачи с главной

На главной выберите «Чат», чтобы просто написать агенту. Сообщение откроет обычный чат без карточки задачи. Для трекера и релизных веток выберите «Задача». У каждого режима свой черновик. Поле задачи называется «Задача для агента». Что можно написать:

- ссылку на задачу из трекера;
- ключ задачи, например `PROJ-123`;
- обычную фразу: что нужно сделать.

Введите задачу и нажмите **«Запустить»** или Enter. Shift+Enter переносит строку. Рядом с запуском виден режим доступа. Если зарегистрировано несколько отдельных проектов, выберите нужный.

**«Параметры»** открывают выбор агента и модели, рабочую папку, заметку и ветки. Для пустой задачи доступны заготовки про SDD, объяснение кода и оценку работы. Для задач по ссылке можно развернуть «Будет отправлено» и прочитать команду целиком.

По умолчанию работа идёт в базовую ветку. В параметрах кнопка «＋ релиз» добавляет ветку вручную. Фразу «только в релиз 54» агент получит и при свёрнутых параметрах. Распознанная ветка или сообщение о том, что её не удалось найти, появится рядом с полем.

Что ещё может случиться:

- «Трекер не ответил (…): агент запущен по тексту». Вы дали ключ или ссылку, но harness не смог получить задачу из трекера, поэтому агент получил вашу строку как есть.
- «Задача уже в работе: открыл текущую сессию». Если по этой задаче уже работает агент, второй не запускается: вы попадаете в существующий чат.
- «Не удалось запустить: …». Причина написана под полем.

Ниже на экране три списка того, что вы уже передали:

- **«Ждут вас»** — агенты, которым нужен ваш ответ или разрешение, которым нужно войти, или прерванные сессии;
- **«Работают»**;
- **«Ответили за сутки»** — закончили ход за последние сутки (показаны первые пять, остальные по кнопке «Ещё N»).

В строке справа есть кнопки «Открыть чат», «Доработать» (отправить задачу агенту на правки) и «Изменения» (открыть панель изменений).

### 4.2. «Задачи»

Экран «Задачи» нужен, если у вас подключён трекер или вы хотите вести список задач внутри harness. Вверху переключатель «Список» / «Доска», поиск «Поиск задач», «Фильтры», «Все статусы», «Скрытые».

Откуда берутся задачи:

- «Синхронизировать» — подтянуть назначенные на вас задачи из трекера (если он включён в «Настройках»);
- «Добавить по ключу» — вписать `PROJ-1234` или ссылку, и задача появится на доске;
- «Новая задача» — завести задачу вручную (на доске можно ещё добавить её в нужную колонку значком «+» у колонки).

В режиме «Список» у каждой задачи есть кнопка **«Передать агенту»**. На карточке доски она тоже есть. Нажатие открывает небольшое окно с полем «Заметки для агента» и строкой «Влить в:». Кнопка «Передать агенту» в нём делает то же самое, что «Запустить» на «Главной»: задача отправляется ссылкой или ключом, агент сам выбирает проект. Когда агент уже работает, вместо этого показывается «Открыть сессию» (а у выполненной задачи — «Открыть результат»).

Карточка задачи (по клику) открывается справа. В ней:

- описание и название можно править;
- кнопки «Передать агенту», «Доработать», «Открыть сессию» (какая из них показана, зависит от состояния);
- блок «Настроить запуск» → «Взять в работу в репозитории…»: если вы хотите сами указать, где работать. В окне поле «Где» предлагает «Все проекты — агент выберет репозиторий по SDD» или конкретный репозиторий. Кнопка «Настроить…» открывает полный диалог запуска;
- «Подзадачи» и «Добавить подзадачу» — если спецификация затрагивает несколько репозиториев, заводится по одной подзадаче на репозиторий, и главный агент (координатор) раздаёт их, каждую в свой репозиторий;
- «Рабочие деревья задачи», «Пулл-реквесты», «Портирование» (перенос в релизную ветку), «Журнал»;
- меню «Ещё действия»: «Назначить агенту…», «Отправить в сессию…», «Скрыть с доски» / «Удалить задачу».

Перенос карточки между колонками не меняет статус в трекере: статус в трекере меняется отдельной формой «Статус в трекере» в карточке.

### 4.3. Обычный чат

Если нужен просто разговор с агентом, без задачи:

- в боковой панели у проекта (или у «Все проекты») есть значок «Новый чат»;
- в верхней панели кнопка «+» у вкладок («Новая вкладка в этом дереве») предлагает «Новый чат», «Новый терминал», «Новый чат с настройками…», «Новый чат в папке…». Закрытие вкладки терминала закрывает и сам терминал: харнес спросит «Закрыть терминал?», потому что всё запущенное в нём завершится. Чтобы терминал работал дальше (например, сборка или сервер), просто переключитесь на другую вкладку: он останется в боковой панели со значком «⌨».;
- на экране «Агенты» есть «Новый чат…».

«Новый чат с настройками…» открывает диалог: где запустить («Все проекты», «Проект» или «Папка…»), «Первое сообщение» (можно оставить пустым), а под «Ещё:» агент, режим подтверждений, роль («Один агент» или «Координатор») и название. «Доп. папки» дают агенту доступ к ещё одним папкам. Координатор разбивает работу на задачи и запускает исполнителей, каждого в своём чате.

### 4.4. Режимы подтверждений

Режим решает, что агент вправе делать без вашего вопроса. Он выбирается в поле «Режим» (на «Главной», в диалоге чата, в строке под вводом чата, а значение по умолчанию задаётся в «Настройках»). Режимов четыре:

- **«План»** — «Только план — ничего не меняет». Агент читает и предлагает, но файлы не трогает. Хороший выбор для аналитика, когда нужно только объяснение или оценка.
- **«С подтверждением»** — «Спрашивать перед действиями». Самый осторожный режим, зато вопросов много.
- **«Авто-правки»** — «Правки файлов без подтверждения».
- **«Полный доступ»** — «правки + разрешённые команды без вопросов». Агент сам правит файлы и запускает безопасные, заранее разрешённые команды (например, `git`), не прерывая вас. Режим удобен, когда вы доверяете агенту задачу и хотите получить результат без постоянных вопросов. Он подсвечивается в списке, чтобы вы не включили его случайно.

Важно: «Полный доступ» не означает «можно всё». У GigaCode нет режима «разрешить абсолютно всё», поэтому harness заранее разрешает агенту обычные команды, а остальное по-прежнему может быть отклонено. Тогда в чате появится карточка «CLI отклонил: …» (см. раздел 6), и вы решаете, что делать.

Если у вас сомнения, начните с «Авто-правки» или «С подтверждением». Для задач на объяснение и оценку подойдёт «План».

## 5. Как следить за работой

### Боковая панель

Слева постоянно видна боковая панель. Верхние пункты: «Главная», «Задачи», «Агенты», «Пулл-реквесты», «Входящие». У «Агенты» рядом с названием могут быть счётчики «работают» и «ждут вас». Рядом с «Пулл-реквесты» и «Входящие» тоже стоят счётчики.

Под ними:

- **«Закреплённые»** — чаты, которые вы закрепили: меню чата (правая кнопка или «⋯») → «Закрепить вверху». Блок стоит над всеми остальными, чаты в нём идут в порядке закрепления; «Открепить» в том же меню убирает чат из блока, сам чат остаётся на своём месте в списке.
- **«Ждут вас»** — самый важный блок. Сюда попадают чаты, которым нужны вы: просят разрешение (подпись «разрешение»), задали вопрос («вопрос»), требуют войти («вход»), молчат слишком долго («нет вывода …»), упали («ошибка»), были прерваны. Пока блок пуст, ничего не требует вашего внимания. Сюда же попадает чат, в котором агент закончил задачу и ждёт проверки (подпись «проверить»): пока во «Входящих» не прочитано его «готово», «не выполнена» или «закончил ход без отчёта». И чат, где агент ответил, пока вы были в другом месте (подпись «ответил»; в списке чатов у него зелёный значок и жирный заголовок): он остаётся здесь, пока вы его не откроете. Такой, упавший или прерванный чат можно убрать из блока крестиком «×» (появляется при наведении): сам чат останется в списке, а если он снова упадёт, вернётся в блок. Через сутки такие чаты уходят из блока сами.
- **«В работе»** — чаты, где агент сейчас выполняет ход.
- **«Проекты»** — дерево: проект, под ним рабочие деревья (с метками `±N` — число изменённых файлов, `↑N` — число коммитов, ещё не вошедших в базовую ветку, `N ▶` — сколько агентов работает, `⚠N` — сколько чатов ждёт вас), под ними чаты. Помощники основного агента показаны под ним со знаком `↳`. Чаты, начатые в самом GigaCode CLI, отмечены значком «из CLI». Кнопка «Параметры рабочих пространств» (значок ползунков в заголовке «Проекты») открывает настройки отображения: группировку, сортировку, переключатель «Чаты из CLI», «Скрывать чаты старше» (1, 3, 6, 12 часов или несколько дней). Кнопка чата у ветки открывает чат в этом рабочем дереве. Терминал доступен в меню дерева. Работающие помощники видны в боковой панели, завершённые чаты доступны под родителем в строке «Завершённые».
- «Настройки» и переключатель темы внизу.

В поле «Поиск» вверху можно искать по чатам и проектам. «Команда» в верхней панели (Ctrl+K на Windows и Linux, ⌘K на macOS) открывает палитру команд.

### «Агенты»

Доска агентов показывает все чаты по колонкам:

- «Ждут вас» — вопрос, разрешение, вход или прерваны;
- «Ошибки» — упали или завершились;
- «Работают» — идёт ход;
- «Ответили» — ход закончен, можно писать дальше;
- «Задача выполнена» — агент задачи отчитался.

Пустые колонки могут не показываться. Вверху переключатель «Активные» / «Архив». На карточке видны название чата, подпись «↳ от <родительский чат>» для помощников, «в очереди N» (сообщения в очереди), последнее сообщение агента и кнопки: «Написать агенту» (быстро отправить сообщение, оно встанет в очередь, если агент занят), меню «Ещё действия» с пунктом «Дать задачу…» (отправить агенту задачу из бэклога), для архивных чатов «Вернуть». Нажатие на вопрос агента на карточке открывает чат, чтобы ответить.

### «Входящие»

Сюда приходят вопросы агентов, отчёты исполнителей и ошибки. Над списком есть блок «Ждут вас» и, если были перезапуски, блок «Прерванные сессии» с кнопками продолжить или отпустить. Для сообщений доступны «Ответить» (прямо в карточке, Enter отправляет), «Открыть чат», «Доработать», «Проверить изменения» (открывает рабочее дерево задачи) и «Прочитано». Кнопка «Прочитать все» очищает список. Число непрочитанного видно в заголовке вкладки браузера. Если вы разрешили уведомления на рабочем столе («Настройки» → «Рабочее место» → «Общие»), браузер напомнит вам, когда агент ждёт ответа.

### Строка активности чата

Внутри чата вы видите, что делает агент, без чтения всей переписки:

- «Работает 14 с» — таймер хода; после окончания он превращается в «Работал …»;
- текущее действие: «Думает», «Пишет ответ», «Выполняет: <инструмент>», «Завершает ход…»;
- сгруппированные шаги (прочитал файл, выполнил команду) с возможностью раскрыть детали;
- карточка «Изменено N файлов» с `+добавлено −удалено` и кнопкой «Открыть дифф»;
- разделитель «Новое», чтобы не потерять место, где появились новые сообщения;
- если агент ждёт вас, над вводом появляется полоса «Ждёт вашего ответа — показать вопрос» или «Ждёт вашего разрешения — показать».

Если вывода нет слишком долго, появляется строка «Нет вывода … Процесс жив, но молчит» с кнопками «Подождать» и «Остановить» (подробнее в разделе 11).

В шапке чата: название (его можно переименовать), «Доработать» (если чат связан с задачей), «Стоп», «Изменения» (открыть панель изменений), меню «Ещё» («Разрешения этого чата…», «Лог агента», «Сбросить статус», «Удалить сессию»), индикатор MCP-серверов (по нажатию видно, какие запустились) и «Папки» (дополнительные папки агента).

### Помощники (субагенты)

Если сообщение начинается с вашей команды GigaCode (например, `/full-task <ссылка> …`, файл в `~/.gigacode/commands`), харнес, как и CLI в терминале, отправляет агенту сам текст команды с вашими словами на месте `{{args}}`. В чате остаётся то, что вы написали, а под ним свёрнутая строка «Текст команды /full-task · N строк»: нажатие показывает, что именно получил агент.

Когда основной агент запускает помощников, каждый из них получает собственный чат. Он вложен под основным в боковой панели и отмечен «↳»; в названии у ревьюера есть «ревью ·». Панель помощников в чате основного агента показывает число агентов, «В работе: N», у каждого строку «что делает», токены и кнопки «Остановить» (пока работает) и «Убрать» (когда закончил). Чат помощника можно открыть, прочитать и ответить в нём. В шапке его чата написано «субагент» и указан чат, который его запустил (нажатие открывает тот чат). Закончивший помощник уходит в архив, но если основной агент даёт ему новую работу, он возвращается в список, пока работает, а его ответ приходит основному агенту сообщением. Карточка «Субагент <тип>» в основном чате содержит кнопку «Открыть чат субагента».

Некоторые помощники встроены в сам GigaCode: они работают внутри процесса родительского чата, и harness показывает их как чаты только для чтения («Внутренний субагент GigaCode: писать можно в родительский чат»). Отдельно их не остановить: «Остановить» там остановит весь ход родительского чата, и harness спросит подтверждение.

Основной путь, которым harness хочет работать с помощниками, описан в «Настройках» → «Оркестрация»: переключатель «Субагенты отдельными чатами (через harness)». Для него нужен навык `harness-orchestration` (его устанавливает мастер первого запуска или сама эта настройка).

## 6. Как отвечать агенту

### Вопрос агента

Когда агенту нужно что-то уточнить, в чате появляется карточка «Агент спрашивает». В ней варианты ответа (кнопки или флажки для выбора нескольких с кнопкой «Ответить») и поле «Свой ответ» («Или свой ответ…» / «Ваш ответ…»). Ответить можно и обычным сообщением в строке ввода. После ответа карточка сворачивается в «Вы ответили: …». Такие же карточки приходят во «Входящие», и там тоже можно нажать «Ответить». Агент ждёт ответа на месте, не продолжая работу, до 30 минут (`orchestration.askWaitMin` в конфиге): ваш ответ сразу попадает ему, а не в очередь. Если за это время ответа нет, агент завершает ход, а ваш ответ потом запустит следующий.

### Карточка разрешения

Когда агент хочет сделать что-то, чего ему не разрешено автоматически (выполнить команду, изменить файл, вызвать MCP-инструмент), в чате появляется карточка. Есть два вида.

- **«Агент просит разрешение»** — запрос ещё не выполнен, агент ждёт ответа.
- **«CLI отклонил: …»** — агент попытался, но CLI отказал. Вы можете разрешить и повторить.

На карточке написано, что именно хотел сделать агент («Выполнить команду: …», «Изменить файл: …»). Под заголовком «Подробности» раскрываются технические детали и исходный текст запроса. Для отказов также показывается «Будет разрешено: <шаблон>», то есть что именно вы разрешаете.

Кнопки в обычном (headless) режиме запуска:

- **«Разрешить и повторить»** — разрешить один раз; запрос уходит заново.
- **«Разрешать всегда в этом проекте»** — разрешение запоминается для проекта и действует во всех его чатах. Список можно смотреть и править в «Настройках» → «Разрешённые команды по проектам».
- **«Разрешать всегда в этой сессии»** — разрешение действует только в этом чате. Список видно в меню «Ещё» → «Разрешения этого чата…», крестик убирает пункт.
- **«Оставить отклонённым»** — не разрешать.

Под кнопками есть ссылка «Добавить пояснение к отказу»: поле «Почему нет или что сделать вместо (необязательно)» позволяет сказать агенту, что делать вместо запрещённого действия. Клавиша Enter подтверждает главное действие, Esc переводит фокус на отказ.

Принятое решение остаётся в чате короткой строкой: «Разрешено один раз», «Разрешено в этом проекте», «Разрешено в этой сессии», «Запрещено».

Чтобы вопросов было меньше, а не «разрешать всё подряд», добавляйте только безопасные команды. Подробнее в разделе 11.

### Сообщение работающему агенту: очередь

Писать в чат можно и тогда, когда агент занят: в строке ввода будет подсказка «Сообщение встанет в очередь», а кнопка станет «Поставить в очередь». Сообщение уйдёт после текущего шага. Над строкой ввода показан список «Очередь сообщений»:

- «В очереди: N — уйдёт после текущего шага», пока агент работает;
- «В очереди: N — агент сейчас не работает» и ссылка **«Отправить сейчас»**, если агент простаивает, а сообщение ещё ждёт;
- у каждого вашего сообщения есть карандаш («Изменить: вернуть в поле ввода») и крестик («Отменить: убрать из очереди»). Сообщения, которые поставил в очередь другой агент, помечены «от агента:».

Кнопка «Остановить агента» (квадрат) в строке ввода прерывает ход.

### Вложения и скриншоты

- Кнопка **«+»** («Приложить файл») открывает системный диалог выбора файлов (можно сразу несколько). Файл копируется в папку чата, а агент получает путь к нему.
- **Ctrl+V** с картинкой в буфере (скриншот) вставляет её как файл. Файл можно и перетащить в поле ввода.
- В текст на место курсора встаёт метка **«[Изображение №1]»** (для картинки) или **«[Файл №2]»** (для остального: текст, docx, лог). Номер совпадает с номером в списке вложений, который получает агент, так что он понимает, к какой части вопроса относится файл. Метку можно передвинуть или стереть, как обычный текст. Если убрать вложение крестиком, его метка исчезнет, а номера следующих сдвинутся.
- Карточка вложения над полем ввода и файл в отправленном сообщении открываются кликом в своей программе. Кнопка с папкой рядом с файлом (**«Показать в папке»**) открывает проводник с выделенным файлом. Картинка в чате раскрывается по клику, там же есть кнопки «Открыть» и «Показать в папке». Программы и скрипты (`.exe`, `.bat`, `.ps1`…) кликом не запускаются: вместо этого откроется их папка.
- Символ **«@»** в сообщении позволяет сослаться на файл проекта, **«/»** подставляет команды агента.

### Комментарий к строке диффа

Если вы смотрите изменения и видите, что в конкретном месте нужно поправить, не пишите про это абстрактно:

1. Откройте дифф (в панели изменений «Просмотреть всё» или значок «Открыть дифф» в карточке «Изменено N файлов»).
2. Наведите на строку и нажмите «+» («Комментарий агенту к строке …»). Чтобы выбрать диапазон, нажмите «+» на второй строке с зажатым Shift.
3. В поле «Что поправить агенту» напишите, что изменить. Под ним выберите чат в списке «Какому чату отправить» (подойдёт тот, что открыт в этом рабочем дереве, или «Новый чат») и нажмите «Отправить».

Агент получит ваш текст вместе с именем файла, номерами строк и самими строками. Если агент занят, сообщение встанет в очередь («Отправлено в «…» — в очередь»). В редакторе файла то же делает кнопка «Агенту»: она берёт выделенные строки (или строку с курсором).

## 7. Как довести работу до PR

Когда агент закончил, результат находится в его рабочем дереве, то есть в отдельной папке и ветке. Основной код проекта не изменён.

### Откуда открыть изменения

- кнопка «Изменения» в шапке чата;
- значок «Изменения» в строке на «Главной»;
- «Проверить изменения» во «Входящих»;
- «Коммит» / «Дифф» на карточке задачи.

Справа откроется панель с вкладками (в том числе «Изменения» и «Файлы»). Её можно скрыть и показать кнопкой «Панель файлов и изменений».

### Строка пути

Вверху панели «Изменения» показан путь «Коммит → Push → PR → Влит» («Путь до вливания») с подсвеченным текущим шагом. Рядом строка «Дальше: …» объясняет, что делать, и там, где рядом нет подходящей кнопки, даёт свою:

- «Дальше: проверить N файлов и закоммитить» и кнопка «Посмотреть изменения»;
- «Дальше: отправить ветку в origin» (или «отправить N коммитов в origin»);
- «Дальше: открыть пулл-реквест» и кнопка «Создать PR»; если интеграция PR не настроена, кнопка «Настроить»;
- после создания PR шаг «Влит» меняется на «На ревью», пока PR не влит: «Дальше: дождаться ревью и вливания» (или «назначить ревьюеров и дождаться вливания»);
- «PR влит — рабочее дерево больше не нужно» и кнопка «Убрать дерево…»;
- «PR отклонён — поправить и создать заново».

Для основной ветки, когда в ней ничего не изменено, строка пути не показывается.

### Просмотр диффа

Список изменённых файлов сгруппирован: «Проиндексировано» и «Изменения». У каждого файла статус (изменён, добавлен, удалён, новый, конфликт) и `+N −M`. Нажатие на файл раскрывает изменения. «Просмотреть всё» (или в меню «Ещё» → «Просмотреть весь дифф») открывает все изменения во вкладке. Файлы, которые не должны попасть в коммит, собраны под «Не коммитятся»: служебные папки (`.superpowers/`, `.gigacode/tmp/`), скомпилированные классы `*.class` и логи `*.log` — например, если агент собрал код или записал вывод тестов прямо в рабочем дереве. Список задаёт `git.excludeFromCommit` в конфиге. При наведении на файл появляются кнопки «Открыть файл», «Отменить изменения» и «Добавить в индекс». Отмена откатывает файл, но перед этим спрашивает подтверждение. «↶» в заголовке группы «Изменения» и «Отменить все» под «Не коммитятся» отменяют сразу всю группу: новые файлы удаляются, изменённые возвращаются к последнему коммиту (тоже с подтверждением).

### Коммит

1. В поле «Сообщение» уже будет написан текст: harness просит агента сгенерировать его по изменениям и задаче («GigaCode пишет сообщение… N с»). Это можно отключить («Настройки» → «Git»). Кнопка «Сгенерировать сообщение» (значок) напишет заново, если вам не понравилось. Текст можно править: первая строка считается заголовком, и её лучше держать короткой.
2. Основная кнопка меняется по обстоятельствам: **«Закоммитить всё»**, «Закоммитить выбранные (N)», если вы отметили файлы («Добавить в индекс»), и «Push ↑N» после коммита. Если ветка ещё нигде не опубликована, кнопка превращается в **«Опубликовать ветку»**.
3. Стрелка рядом с кнопкой («Другие действия») даёт «Закоммитить и отправить», «Только push» и «Создать PR».

### Через агента или напрямую

Пока harness выполняет коммит, push и создание PR, он может поручить это самому агенту или сделать сам. Выбор — в меню «Ещё» панели изменений (или в «Настройках» → «Git» → «Коммит, push и PR»).

- **«Через агента»** (по умолчанию). Агент выполняет git-команды сам, поэтому работают его хуки и навыки (например, проверки перед коммитом). Под кнопкой видно «Агент коммитит…», «Агент отправляет ветку…» или «Агент создаёт PR…», время и ссылка «открыть чат», а в конце результат.
- **«Напрямую»**. Git запускает сам harness, без агента.

Если через агента не получилось, под кнопками появится «Не вышло через агента: …» с кнопками «Открыть чат» и **«Сделать напрямую»**: эта кнопка повторит действие в обход агента.

### Push

Если ветки ещё нет на сервере, нужна кнопка «Опубликовать ветку». Если ветка уже есть, а у вас коммитов больше, чем у сервера, увидите «Push ↑N». Рядом в панели видно `↑N ↓M`: сколько у вас коммитов, которых нет на сервере, и наоборот. Ссылка «Открыть ветку в репозитории» ведёт на неё в веб-интерфейсе.

### «Создать PR»

«Создать PR» открывает окно «Создать pull request»: «Заголовок», «Описание» (переключатель «Текст» / «Просмотр», в описании подставлены ключ и название задачи, отчёт агента и список коммитов; при желании их можно сгенерировать повторно), и под «Ещё: в ветку …» целевая ветка. Нажмите «Создать PR». Если PR для этой ветки уже есть, harness не создаст второй, а скажет «PR уже открыт». После создания в панели появится ссылка «Открыть PR #N».

### Следить до «Влит»

- Экран «Пулл-реквесты». Вверху переключатель «Мои» (ваши открытые PR во всех репозиториях; логин берётся из sourcecontrol или из имени пользователя ОС, его можно уточнить в «Настройках» → «Pull requests») и «По задачам» (PR веток задач harness). Слева у каждого PR его состояние одним словом: «Одобрен», «Одобрен 1 из 2», «Ждёт ревью · 0 из 2», «Просят изменения», «Конфликт» или «Без ревьюеров». Дальше ветки «ветка → целевая», ревьюеры (наведите, чтобы увидеть, кто что ответил) и кнопки к задаче и к чату агента. Справа «Влить» (выделена, когда PR одобрен; недоступна при конфликте) и «Закрыть» — обе спрашивают подтверждение, — и значок открытия PR в браузере. Нажатие на строку открывает PR прямо в харнесе: справа выезжает панель с состоянием, ветками, ревьюерами (кто что ответил), кнопками «Влить» / «Закрыть» / «Открыть в браузере» и двумя вкладками — «Изменения» (дифф по файлам, как в панели изменений) и «Комментарии» (автор, когда, к какому файлу и строке). Если сервис кода не отдал дифф, харнес показывает его по локальным веткам и пишет об этом. Закрыть панель — крестик или Esc. «Обновить» перечитывает данные.
- Счётчик рядом с «Пулл-реквесты» в боковой панели.
- Путь «Коммит → Push → PR → Влит» в панели изменений.

Если интеграция PR не настроена, экран покажет «PR-интеграция не настроена» и кнопку «Настроить»: нужен MCP-сервер sourcecontrol (см. docs/INTEGRATION.md).

### Перенос в релиз

Если при передаче задачи вы указали релизную ветку («Влить в: … release/1.54.0»), основная работа выполняется один раз, а в релиз изменения переносятся отдельной веткой и отдельным PR. В карточке задачи раздел «Портирование» показывает по каждой целевой ветке «не перенесено», «перенесено», «конфликт» (агент разбирается с ним), «готово» или «ошибка» и кнопку «Портировать в <ветка>». Для переноса у задачи должна быть рабочая ветка.

### Убрать рабочее дерево

Когда PR влит, дерево больше не нужно.

- В панели изменений нажмите «Убрать дерево…».
- Или в боковой панели нажмите на «…» у рабочего дерева («Действия с деревом») и выберите «Удалить рабочее дерево». Там же можно выбрать, что сделать с веткой: «Не удалять ветку», «Удалить, если слита» или «Удалить принудительно». Если в дереве есть несохранённая работа или в нём работает агент, harness предупредит об этом списком, и без отметки «Я понимаю, изменения будут потеряны» не продолжит.
- «Очистить рабочие деревья…» в меню проекта показывает список деревьев, чья задача готова или PR влит, без изменений и без работающих агентов, и удаляет выбранные сразу пачкой.

В меню рабочего дерева есть и полезные мелочи: «Закрепить» / «Открепить», «Перевести в сон» / «Разбудить», «Изменить сведения…» (название и заметка), «Открыть папку», «Копировать ветку».

### Проверка перед «готово»

Чтобы «готово» значило «проверено», а не «агент так сказал», задайте проекту команду проверки: «Настройки» → «Агенты» →
«Проверки проектов». Для каждого проекта — своя команда (тесты, линтер), кнопка «Подставить» предлагает её по файлам
репозитория (`npm test`, `mvn -q test`…), «Проверить сейчас» запускает её тут же.

Когда агент сдаёт задачу, программа сама запускает эту команду в его рабочем дереве. Не прошла — агент получает вывод и
исправляет (сколько раз — «Попыток исправить»); на карточке задачи в это время «проверка…». Не исправил — вам уведомление.

## 8. Ничего не теряется

### Перезапуск harness или компьютера

Агенты запускаются отдельными процессами. Если вы перезапустили сам harness, работающие агенты продолжают работу, и harness подхватывает их заново. История чатов и очередь сообщений хранятся на диске (в `data/`).

Если выключился компьютер или процесс упал, ход агента прервался. После запуска harness откроется окно **«Восстановление сессий»**. В нём перечислены прерванные чаты и причина («Перезагрузка ПК», «Перезапуск harness», «Сбой»). Отмеченным чатам уйдёт сообщение из поля «Сообщение агентам», и они продолжат с того места, где остановились. Кнопка «Продолжить выбранные (N)» делает это; «Закрыть» откладывает решение; пункт «Не продолжать — убрать из списка» отпускает чат. То, что осталось, видно во «Входящих» в блоке «Прерванные сессии». В «Настройках» → «Общие» можно включить автоматическое продолжение («Продолжать прерванные сессии автоматически»).

Если сервер был перезапущен, а страница в браузере осталась открытой, вы увидите «Сервер перезапущен — обновите страницу»: нажмите «Обновить». Вкладки и черновики сохранятся, а несохранённые правки в открытых файлах будут потеряны.

### Агент оборвался или замолчал

Если ход оборвался посреди работы (ошибка, обрыв связи), программа сама продолжает ту же сессию с того же места: в чате будет
«продолжу сам через 30 с (попытка 1 из 3)». Файлы в рабочем дереве и контекст сохраняются. Если агент долго молчит и при этом не
выполняет команду, его будят так же. Попытки кончились — во «Входящих» уведомление с кнопкой «Повторить»; та же кнопка есть в
чате с ошибкой. Сколько попыток и через сколько будить — «Настройки» → «Общие».

### Черновики

Тексты, которые вы начали писать на «Главной» (задача и заметки), в комментарии к строке и в сообщении коммита, сохраняются в браузере и не пропадают при перезагрузке страницы.

### Чаты, начатые в терминале («История CLI»)

Если вы раньше работали с GigaCode прямо в терминале, ваши чаты не потеряны:

- Harness сам подхватывает недавние (за последние дни) чаты CLI и показывает их в боковой панели как обычные чаты со значком «из CLI». Их можно продолжить. Чтобы скрыть их, выключите «Чаты из CLI» в «Параметры рабочих пространств».
- Во вкладке панели **«История CLI»** (рядом с «Изменения» и «Файлы») перечислены сессии CLI для этой папки. Есть фильтр. Нажатие открывает сессию только для чтения, а кнопка **«Продолжить в harness»** превращает её в обычный чат, который идёт дальше с того же места. Пометка «открыта в harness» стоит у сессий, которые уже подхвачены.

### Архив

Чат, который вам больше не нужен, лучше не удалять, а убрать в архив:

- меню чата в боковой панели («Действия с чатом») → «В архив». Если агент в этот момент работает, harness предупредит, что остановит его; история сохранится;
- чаты без активности дольше заданного срока уходят в архив сами (по умолчанию через 7 дней; «Настройки» → «Общие» → «Автоархив неактивных чатов через»);
- архивные чаты открываются только для чтения. Вернуть их можно кнопкой «Вернуть из архива» (в чате), «Вернуть» (на экране «Агенты», режим «Архив») или пунктом меню «Вернуть из архива».

«Удалить…» стирает историю чата безвозвратно (с подтверждением).

## 9. Сценарии

### а) Разработчик: задача из трекера до PR

1. «Главная» → вставьте ссылку или ключ `PROJ-123`. При необходимости откройте «Параметры» и напишите ограничения. Проверьте строку «Будет отправлено:». Если нужен ещё и релиз, нажмите «＋ релиз» в строке «Влить в:». Выберите «Режим» (например, «Авто-правки»). Нажмите «Запустить».
2. Откроется чат агента. Он создаст ветку и рабочее дерево и начнёт работу. Следите за строкой активности («Выполняет: …»). Можно закрыть чат и заняться другим: блок «Ждут вас» и счётчики в боковой панели сообщат, когда понадобитесь.
3. Если агент спросил или попросил разрешение, ответьте в карточке (раздел 6).
4. Когда агент закончил (чат попал в «Ответили»), откройте панель «Изменения». Посмотрите дифф. Если что-то не так, оставьте комментарий к строке или напишите в чат; для крупных правок нажмите «Доработать» и опишите, что поправить.
5. Нажмите «Закоммитить всё», затем «Опубликовать ветку», затем «Создать PR» (или сразу «Закоммитить и отправить», затем «Создать PR» через стрелку). Проверьте заголовок и описание.
6. Следите за шагом «На ревью» и на экране «Пулл-реквесты». Когда PR влит, нажмите «Убрать дерево…».

### б) Аналитик: результат без git

Аналитику не нужно знать, что такое ветка или коммит. Нужно сформулировать задание и забрать результат. Если проекты лежат в нескольких папках, попросите коллегу один раз настроить «Папку со всеми проектами» (раздел 3), и дальше вы просто пишете задание.

Для таких заданий разумно выбрать режим «План», а если результатом должен стать документ в репозитории, то «Авто-правки».

**Спецификация по SDD к задаче**

- Что ввести на «Главной»: «спецификация по SDD» в параметрах задачи, затем допишите ключ: «Подготовь спецификацию по SDD к задаче PROJ-123».
- Что смотреть: чат. Агент прочитает задачу и код и может задать вопросы (карточка «Агент спрашивает»), ответьте на них. Идущая работа видна в строке «Выполняет: …».
- Как понять, что закончено: чат перешёл в «Ответили», а в боковой панели исчезла строка «В работе». Последнее сообщение агента обычно содержит итог.
- Где результат: если агент создал файл (например, `spec.md`), он появится в карточке «Изменено N файлов» в чате и в панели «Изменения» (значок «Открыть файл» откроет его). Откройте его во вкладке «Файлы» или по ссылке в карточке. Если же нужно, чтобы документ попал в репозиторий, попросите агента закоммитить и создать PR либо передайте это разработчику, нажав «Закоммитить всё» в панели «Изменения» (git знать не нужно: сообщение уже сгенерировано).

**Объяснить, как устроено**

- Что ввести: «объяснить, как устроено» → «Объясни простыми словами, как устроено платёжный модуль: что он делает и откуда берёт данные». Режим «План» достаточен.
- Что смотреть: ответ появится прямо в чате обычным текстом. Можно задавать уточняющие вопросы, продолжая тот же чат.
- Как понять, что закончено: ход завершился, чат перешёл в «Ответили».
- Где результат: сам ответ в чате. Файлы создаются только если вы попросили записать пояснение в документ.

**Оценить задачу**

- Что ввести: «оценить задачу» → «Оцени задачу: что придётся поменять и какие есть риски — PROJ-123».
- Что смотреть и где результат: так же, ответ в чате. Если нужно сохранить его, попросите в следующем сообщении: «Сохрани оценку в файл docs/estimate-PROJ-123.md».

Во всех случаях в панели «Изменения» нет ничего, кроме файлов, которые агент создал по вашей просьбе, а при режиме «План» их не будет вовсе.

### в) Несколько задач сразу

1. Передавайте задачи по очереди с «Главной»: после «Запустить» поле очищается, и можно сразу писать следующую. Каждая задача получает свой чат, свою ветку и своё рабочее дерево, поэтому они не мешают друг другу.
2. На экране «Агенты» видны все задачи по колонкам. Блок «Ждут вас» в боковой панели собирает только те чаты, где нужен ваш ответ.
3. Отвечайте по мере того, как задачи просят внимания: либо в чате, либо прямо во «Входящих» («Ответить»).
4. Если задача содержит несколько частей в разных репозиториях, заведите подзадачи (в карточке задачи «Добавить подзадачу» по одной на репозиторий). Главный агент раздаст их, а каждая подзадача получит свой чат.
5. Закончившиеся задачи проверяйте по одной: в «Ответили» откройте чат, затем «Изменения». Не забывайте убирать влитые рабочие деревья.

## 10. Настройки

На экране «Настройки» четыре раздела. Можно перейти между ними, а затем сохранить изменения одной кнопкой внизу.

- **Рабочее место** — состояние CLI, вход, модель, разрешения, папка проектов, оформление и восстановление чатов.
- **Агенты** — запуск процесса, команды задач, уровни моделей, инструменты, помощники и проверки перед завершением.
- **Подключения** — серверы MCP, ключи доступа, импорт из трекера и создание пулл-реквестов. Порядок подключения описан в разделе 3.
- **Доска и Git** — колонки, переходы, ветки, коммиты и шаблоны сообщений.

Внизу окна «Подключено» показывает связь браузера с Harness. Нажмите «Сервисы», чтобы увидеть состояние каждого MCP, повторить подключение или перейти в настройки. При ошибке проверки сертификата сверьте доверенную цепочку CA с администратором сервиса.

## 11. Если что-то не так

**Агент не найден.** В мастере или в «Настройки» → «Рабочее место» появится «Не найден <имя>». Введите полный путь к запуску агента в поле «Путь к агенту» и нажмите «Проверить». Раскройте «Подробности», чтобы увидеть исходную ошибку. Для проверки того, что выбрал harness: `node server/index.js --print-config`. Если чат пишет «Агент не запустился», проверьте команду агента в конфигурации и откройте «Лог агента» (меню «Ещё» в шапке чата).

**Агент просит войти.** В чате появляется карточка «GigaCode ждёт авторизацию» со ссылкой («Открыть ссылку», «Скопировать»). Откройте её в браузере и войдите: запуск продолжится сам. Войти можно и из «Настройки» → «Рабочее место» (кнопка «Войти в GigaCode»).

**MCP-сервер с ошибкой.** В строке состояния внизу «MCP: … с ошибкой: N»: нажмите на неё. Если не хватает секрета, допишите его в файл секретов (путь в `HARNESS_MCP_SECRETS` / `CONSOLE_MCP_SECRETS` или `mcpSecretsFile`). Если сервер вам не нужен, выключите его в `harness.config.local.json`: `mcpServers.<имя>.enabled: false`. В шапке чата значок MCP показывает серверы, которые не запустились для этого агента. Серверы самого агента настраиваются в «Настройки» (раздел GigaCode).

**Разрешения спрашиваются слишком часто.** Выберите режим «Авто-правки» или «Полный доступ». Затем в карточках разрешений используйте «Разрешать всегда в этом проекте» для безопасных команд (например, `git status`, запуск тестов). Список можно вести в «Настройки» → «Разрешённые команды» (для всех чатов) и «Разрешённые команды по проектам». Для одного чата есть меню «Ещё» → «Разрешения этого чата…». Не разрешайте «всегда» то, что вы не готовы отдать агенту без проверки.

**Агент «нет вывода» или завис.** Если процесс жив, но давно ничего не присылал, в боковой панели чат попадёт в «Ждут вас» с пометкой «нет вывода …», а в чате появится «Нет вывода … Процесс жив, но молчит». Первые 30–60 секунд после запуска это нормально (холодный старт с MCP). Если долго ничего не происходит, нажмите «Подождать» (скрыть предупреждение на время) или «Остановить», а затем отправьте сообщение «продолжай». Порог срабатывания меняется в «Настройки» → «Агенты» → «Помощники агента» → «Нет вывода» через. Если статус чата не соответствует действительности, попробуйте «Сбросить статус» в меню «Ещё». «Лог агента» показывает stderr процесса.

**Ошибка PR.** Что-то из следующего:

- «PR-интеграция не настроена». Подключите sourcecontrol (docs/INTEGRATION.md), кнопка «Настроить» откроет нужный раздел.
- «Не удалось подготовить PR: …» или «Не вышло через агента: …». Откройте чат агента по кнопке, прочитайте причину. Если дело в хуках или навыках агента, нажмите «Сделать напрямую». Если сработали ограничения на длину заголовка или описания, сократите текст: допустимые пределы показаны в «Настройки» → «Pull requests» → «Ограничения» (кириллица считается по 2 байта на букву).
- В PR «конфликт». Ветка расходится с целевой. Попросите агента разрешить конфликт: напишите в чат, что нужно обновить ветку от целевой и разрешить конфликты.
- Ветка не опубликована. Сначала «Опубликовать ветку».

**Задача по ссылке не подтянулась.** «Трекер не ответил (…): агент запущен по тексту» значит, что агент получил вашу строку как есть. Проверьте, что трекер подключён и MCP-сервер без ошибок, и передайте заново, если это важно.

**Страница пишет «Связь с сервером потеряна».** Сервер остановлен или перезапускается. Запустите `npm start`, страница переподключится сама.

**Кириллица превращается в «?» при вызове API из PowerShell.** Это относится к тем, кто вызывает API harness вручную (обычному пользователю это не нужно). Windows PowerShell 5.1 при отправке строки в `Invoke-RestMethod` портит кириллицу, и сервер отвечает ошибкой 400. Отправляйте UTF-8:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:4777/... `
  -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($json))
```

Либо используйте `node mcp/harness-mcp.js call ...`. Прочие подробности (формы данных, REST, WebSocket) описаны в docs/ARCHITECTURE.md.

# Установка на новом ПК

Короткий путь: поставить Node, клонировать репозиторий, `npm install`, `npm run check`, открыть окно.
Затем один раз выбрать агента и папку проекта в самом приложении. Править код для этого не нужно:
всё специфичное для машины (пути, MCP-серверы, ключи доступа) живёт в двух файлах, которых нет в git.

## Что нужно на машине

| Что | Зачем | Проверка |
|---|---|---|
| Node.js ≥ 22 | сервер, тесты, сборка UI | `node -v` |
| git | рабочие деревья, диффы, коммиты, PR | `git --version` |
| GigaCode CLI | настоящий агент (без него работает демо-агент `mock`) | `gigacode --version` |
| npm-зеркало банка | `npm install` во внутренней сети | `npm config get registry` |

`@lydell/node-pty` и Electron тянут готовые бинарники под текущую ОС. Обычные инструменты сборки
(компилятор C++ и Python) нужны только если для вашей платформы готового бинарника нет — тогда `npm install`
скажет об этом сам.

## Шаги

```powershell
git clone <адрес репозитория> sber-harness
cd sber-harness
npm install
npm run build        # собирает UI в web/dist
npm run check        # что найдено на этой машине и что ещё нужно (код выхода 1, если чего-то нет)
npm run desktop      # окно приложения (или npm start — то же в браузере)
```

`npm run check` проверяет Node, собранный `web/dist`, лаунчер каждого включённого агента и наличие файла
пользовательских MCP-настроек GigaCode. Строки `FAIL` — это ровно то, без чего харнес не запустится; строка
`user MCP settings: … нет` не ошибка: своих MCP-серверов просто не будет.

Окно без терминала — лаунчер `start-harness.cmd` (Windows) или `start-harness.sh` (Linux, macOS) и ярлык к нему, см.
следующий раздел.

## Окно приложения и ярлык

Лаунчер сам доводит установку до рабочего состояния: чинит недоустановленный `node_modules`, при необходимости делает
`npm install` (и докачивает бинарник Electron, если прежняя загрузка оборвалась), собирает UI, если нет `web/dist`, и
открывает окно. Закрыли окно — остановился и сервер, который оно подняло. Уже работающий харнес не трогается: окно
либо присоединяется к нему, либо берёт первый свободный порт и свой каталог `data/<папка>-<порт>`.

Ярлык создаётся один раз (повторный запуск обновляет его, например после переноса папки):

```bash
npm run shortcut
```

| ОС | Первый запуск | Ярлык (`npm run shortcut`) | Журнал запуска |
|---|---|---|---|
| Windows | двойной щелчок по `start-harness.cmd` (консоль закроется сама); `start-harness.cmd --console` — то же с выводом в консоль | `sber-harness.lnk` на рабочем столе и в меню «Пуск» | `%TEMP%\sber-harness-desktop.log` |
| Linux | `./start-harness.sh` в терминале | `~/.local/share/applications/sber-harness.desktop` (меню приложений) и копия на рабочем столе | `${TMPDIR:-/tmp}/sber-harness-desktop.log` |
| macOS | `./start-harness.sh` в Терминале | `~/Applications/sber-harness.app` (Launchpad, Spotlight, Dock) и копия на рабочем столе | `$TMPDIR/sber-harness-desktop.log` |

Журнал пишется, только когда лаунчер запущен без терминала (ярлык, меню, Finder). Если окно так и не появилось, причина —
в конце журнала; в Windows и macOS она же показывается в окне сообщения, в Linux — уведомлением (`notify-send`, если есть).

### Windows

- Ярлык запускает `start-harness.cmd` → скрытый перезапуск (`scripts/start-hidden.cmd` → `scripts/start-hidden.ps1`) →
  `start-harness.cmd --run` → `node scripts\desktop.js --ui` → Electron. Пути с пробелами и кириллицей поддерживаются.
- Нужен `node` в `PATH` (обычная установка Node.js с nodejs.org это делает).

### Linux

- Пакеты, без которых Electron не откроет окно (Debian/Ubuntu):
  `sudo apt install libgtk-3-0 libnss3 libasound2 libgbm1 libxss1 libxtst6` (на Ubuntu 24.04 — `libasound2t64`).
- Пункт меню запускает лаунчер через `/bin/sh`, так что бит исполнения у `start-harness.sh` не обязателен (копия из
  архива тоже запустится). GNOME может попросить «Разрешить запуск» для значка на рабочем столе — это его собственная
  защита; пункт в меню приложений работает без неё.
- Песочница Chromium. Где пространства имён пользователя недоступны (Ubuntu ≥ 23.10 ограничивает их через AppArmor,
  контейнеры, запуск от root), Chromium требует `chrome-sandbox` с владельцем root и битом setuid, а `npm install` его так
  не ставит. Тогда окно запускается с `--no-sandbox` (окно показывает только локальный харнес, внешние ссылки уходят в
  системный браузер). Чтобы оставить песочницу включённой:
  `sudo chown root:root node_modules/electron/dist/chrome-sandbox && sudo chmod 4755 node_modules/electron/dist/chrome-sandbox`.
- Wayland: Electron 45 сам выбирает Wayland или XWayland, отдельных флагов не нужно. Окно группируется под значком
  пункта меню по `StartupWMClass=sber-harness`.

### macOS

- Node.js из Homebrew, nvm, Volta, asdf или fnm находится и при запуске из Finder/Dock, где `PATH` почти пустой: лаунчер
  берёт `PATH` login-оболочки и проверяет обычные папки этих менеджеров.
- `sber-harness.app` — маленький пакет, который только запускает `start-harness.sh` из папки репозитория (поэтому папку
  после `npm run shortcut` не переносят, иначе запустите его снова). Значок в Dock во время работы — это окно Electron
  с иконкой приложения; в строке меню оно называется «Electron», так как используется Electron из `node_modules`, а не
  собранный пакет. ⌘Q закрывает окно и останавливает сервер, который оно подняло.
- Gatekeeper. Пакет создаётся на этой же машине, поэтому карантина у него нет и подпись не нужна. Если репозиторий скачан
  архивом через браузер и macOS блокирует запуск («не удаётся проверить разработчика»), снимите карантин с папки:
  `xattr -dr com.apple.quarantine <папка репозитория>`. При первом запуске из папок «Документы»/«Рабочий стол» macOS
  спросит доступ к ним — разрешите.
- Если сам пакет уже запущен (окно открыто), повторный щелчок по нему ничего не делает: переключитесь на окно через Dock.

Перед первым запуском `npm test` после чистой установки загрузите бинарник Electron, если окно ещё не запускали:

```powershell
node node_modules/electron/install.js
```

## Первый запуск в приложении

1. **Выберите агента** — экран первого запуска предлагает найденных (`gigacode`, демо `mock`). Без GigaCode
   оставьте `mock`: он изображает настоящий CLI, и все сценарии (сабагенты, доска, ревью) работают офлайн.
2. **Откройте папку проекта** — кнопка «Начать работу» добавляет рабочее пространство (любой git-репозиторий).
   Папку можно выбрать в проводнике: путь нигде не захардкожен.
3. **Добавьте MCP-сервисы** — «Настройки» → «MCP-серверы». Уже настроенные в GigaCode серверы подхватываются
   из `~/.gigacode/settings.json` без правок: поставьте `inheritUserMcp` или добавьте свои HTTP/stdio-серверы.
4. **Секреты** — только в файле секретов, не в конфиге. Путь показывает «Настройки» → «MCP-серверы» →
   «Файл секретов» (`HARNESS_MCP_SECRETS` / `mcpSecretsFile`); формат — строки `server/Name=value`, JSON-объект
   или одно голое значение (это `onework/Authorization`). Файл лежит вне репозитория.
5. **Новый чат** — выберите агента и отправьте сообщение. Готово.

Демо целиком, чтобы просто посмотреть на приложение: `npm run demo` (своя папка данных и порт 4778, агент `mock`,
задачи и PR из фикстур, сеть не нужна).

## Что где настраивается

`harness.config.json` — значения по умолчанию, он коммитится, его не правим. Своя машина — `harness.config.local.json`
(в `.gitignore`, глубоко сливается поверх общих значений). Минимальный шаблон:

```json
{
  "port": 4777,
  "dataDir": "./data",
  "workspaces": { "root": null, "repos": [] },
  "agents": {
    "gigacode": { "command": null, "node": null, "cliEntry": null }
  },
  "integrations": {
    "tasks": { "enabled": false },
    "pr": { "enabled": false }
  }
}
```

`null` — значит «определи сам»: `command: null` ищет `gigacode` в `PATH`, затем `~/.gigacode/bin/gigacode`;
`shell: null` берёт PowerShell в Windows и `$SHELL -l` в остальных системах; `workspaces.root: null` оставляет
список проектов пустым до первого выбора в UI. Проверить, что выбралось и почему:

```powershell
node server/index.js --print-config
```

Внутренние имена хостов, коды проектов и абсолютные пути бывшего владельца живут только в локальном конфиге.
Чистый клон без этого файла запускается на любой машине и показывает демо-агента и пустой список проектов.

## Частые вопросы

**`Другой harness (pid …) уже работает с … data`** — каталог данных занят живым харнесом. Откройте существующее окно
или задайте другой `--data-dir` / `--port`. Окно, запущенное ярлыком, делает это само: берёт первый свободный порт
и свой каталог `data/<папка>-<порт>`.

**`Агент не запустился`** — `npm run check` покажет, какой лаунчер не найден. Для GigaCode путь задаётся
в `harness.config.local.json`: `agents.gigacode.command` (исполняемый файл) либо `node` + `cliEntry` (запуск под
конкретным `node.exe`). Найденное значение подсказывает сам `--print-config`.

**Нет Electron / окно не открывается** — сначала журнал запуска (таблица выше) или `start-harness.cmd --console` /
`./start-harness.sh` из терминала. Бинарник Electron докачивает `node node_modules/electron/install.js`, сборку под
текущую ОС принудительно перекачивает `npm i -D electron --force`. Без окна всё работает и в браузере: `npm start`.

**Проверка кроссплатформенности** — `node scripts/check-platform.mjs` ищет в коде предположения о платформе
(`cmd`, PowerShell, жёсткие разделители пути) и падает, если они попали в поставляемый код без платформенного выбора.
